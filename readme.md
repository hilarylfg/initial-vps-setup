## ✨ Возможности

- 🧙 **Интерактивный мастер** — сам спросит всё и покажет план до любых изменений
- 👤 **Отдельный admin-пользователь** — создался, добавлен в `sudo` (NOPASSWD), root по SSH закрыт
- 🔑 **Только SSH-ключи** — ключ ставится, вход по паролю отключается (с защитой от потери доступа)
- 🔍 **Аудит портов** — покажет, что слушается, предупредит о конфликтах с фаерволом
- 🔄 **Обновление системы** — все пакеты и ядро до актуальных
- 🔥 **UFW** — фаервол настроится автоматически, даже если его нет в образе — скрипт установит его сам
- ⚡ **BBR** — congestion control + qdisc `fq`: выше скорость и стабильность на длинных каналах
- 🛡 **Fail2ban** — бан после 4 неудачных входов, с эскалацией до 1 недели
- 🚫 **Отключение IPv6** — опционально, через sysctl, легко обратить
- 🤫 **Блокировка ping** — сервер молчит на входящий ICMP
- 💾 **Swap** — создаётся автоматически на серверах с RAM ≤ 2 ГБ
- 🐳 **Docker** — официальный установщик, admin добавляется в группу `docker`
- 🧹 **Чистка системы** — snap, motd-реклама, опционально cloud-init
- 📦 **Диагностика «из коробки»** — htop, vnstat, iperf3, mtr, speedtest-cli
- ♻️ **Идемпотентность** — повторный запуск безопасен

## ⚡ Быстрый старт

Подключись к серверу и выполни одну команду:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hilarylfg/initial-vps-setup/main/setup.sh)
```

Мастер задаст вопросы и покажет план. Всё, что подтвердишь, применится; ответы можно менять.

Автоматический прогон без вопросов (для быстрого разворачивания однотипных серверов):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hilarylfg/initial-vps-setup/main/setup.sh) \
     --admin deploy \
     --ssh-key "$(cat ~/.ssh/id_ed25519.pub)" \
     --ssh-port 2222 \
     --ports 443/tcp,8443/udp \
     --timezone Europe/Amsterdam
```

> [!WARNING]
> Меняешь порт SSH — после работы скрипта проверь подключение **в новом окне терминала**, не закрывая текущую сессию. Если новый порт не пускает — открой старый через VNC-консоль провайдера (`ufw allow 22/tcp`).

## 🧙 Мастер настройки

Что спросит (везде Enter = значение по умолчанию):

| Вопрос | По умолчанию |
|---|---|
| Настраивать SSH? (порт, харденинг, запрет паролей) | да |
| Таймзона | не менять |
| Hostname | оставить текущий |
| Порт SSH | оставить как есть (текущий определится сам) |
| Пользователь для работы | создать `admin` (`-` — остаться под root) |
| SSH-ключ для admin | вставить свой / взять ключи root / сгенерировать на сервере / пропустить |
| Настраивать фаервол и порты? | да |
| Как открыть порты | перед этим покажет, что слушается: открыть всё слушающееся / список вручную / ничего |
| Обновлять систему? | да |
| Отключить IPv6 | нет |
| Блокировать ping | да |
| Создать swap | да |
| Поставить fail2ban | да |
| Харденинг SSH | да |
| Поставить Docker | да |
| Удалить cloud-init | нет |
| Отключить вход по паролю | да, если на сервере есть ключи |

Отвечаешь «нет» на этап — скрипт его полностью пропускает: sshd, фаервол и apt остаются ровно в том состоянии, в каком были.

В конце мастер покажет **план настройки** — изменения начнутся только после подтверждения.

## 🚩 Флаги запуска

Полный список: `bash setup.sh --help`. Флаг задаёт ответ заранее — такой вопрос в мастере не спрашивается.

| Флаг | Описание |
|---|---|
| `--ssh-port PORT` | сменить порт SSH |
| `--ports 443/tcp,8443/udp` | открыть порты; протокол: `tcp` (по умолчанию), `udp` или `both`; диапазоны: `30000-40000/udp` |
| `--timezone Europe/Moscow` | установить таймзону |
| `--admin USER` | создать пользователя с sudo без пароля (NOPASSWD) |
| `--ssh-key "KEY"` | публичный ключ для admin (или root, если admin не задан); можно несколько раз |
| `--key-from-root` | скопировать ключи из `/root/.ssh/authorized_keys` |
| `--generate-key` | сгенерировать ed25519-пару на сервере (приватный ключ показывается один раз) |
| `--hostname NAME` | задать hostname |
| `--disable-ipv6` | отключить IPv6 |
| `--no-update` | не обновлять систему (apt update/upgrade) |
| `--no-firewall` | **не трогать фаервол и порты вообще** — UFW остаётся как есть (для сервера, где порты уже настроены руками) |
| `--no-ssh` | **не менять настройки sshd вообще** — порт, харденинг и пароли остаются как есть |
| `--no-docker` | не ставить Docker |
| `--no-fail2ban` | пропустить fail2ban |
| `--no-block-ping` | не блокировать ping |
| `--no-swap` | не создавать swap |
| `--no-ssh-harden` | не применять харденинг SSH |
| `--disable-ssh-password` | вход только по ключам. ⚠️ Ключ должен быть **уже на сервере** или передан флагом! |
| `--purge-cloudinit` | удалить cloud-init. ⚠️ Не для всех VPS — часть хостеров через него раздаёт сеть |

## ⚙️ Что делает скрипт

| Шаг | Что происходит | Зачем |
|---|---|---|
| 🔄 Обновление | `apt full-upgrade` | свежие пакеты и ядро, заплатки безопасности |
| 📦 Базовый софт | curl, git, jq, sudo, htop, vnstat, mtr, iperf3 и др. | работа и диагностика |
| 🕐 Время и имя | NTP + таймзона и hostname из мастера | корректные логи и сертификаты |
| 👤 Admin | пользователь + группа `sudo` + NOPASSWD + SSH-ключ | работать не под root |
| 🔑 Ключи | `~/.ssh/authorized_keys` с проверкой каждого ключа | вход без паролей |
| ⚡ BBR | qdisc `fq` + `bbr` | скорость и стабильность |
| 📈 Лимиты | nofile 1M, журнал systemd 200 МБ | много соединений, меньше мусора на диске |
| 🛡 Fail2ban | jail на sshd, бан 1 ч → эскалация до 1 недели | анти-брутфорс |
| 🔍 Аудит портов | `ss -tulnp` + сверка со списком открываемых | не закрыть нужное, не открыть лишнее |
| 🔥 UFW | deny incoming, rate-limit на SSH-порт, порты из мастера | фаервол |
| 🔐 SSH | MaxAuthTries 3, опц. порт, запрет паролей, запрет root | безопасность |
| 💾 Swap | 2 ГБ при RAM ≤ 2 ГБ, иначе 1 ГБ | стабильность на дешёвых VPS |
| 🐳 Docker | официальный установщик, admin в группе `docker` | нужен для деплоя |
| 🧹 Чистка | snap, motd-реклама, кэш apt; опц. cloud-init | меньше мусора в системе |

## 🔐 Доступ к серверу после настройки

- **Работай под admin-пользователем.** Он в группе `sudo`, право root — без пароля (NOPASSWD).
- **Вход по паролю отключён** — только SSH-ключи. Root по SSH закрыт полностью.
- **У admin нет пароля — это осознанно.** Пароль заблокирован, вход только по ключу; sudo срабатывает без пароля.
- **Аварийный вход** — VNC-консоль провайдера: там root доступен со своим паролем (его скрипт не трогает). Это страховка на случай, если ключ потерян.
- Если выбрал «сгенерировать ключ на сервере» — приватный ключ показывается **один раз** и сохраняется в `/root/`. Скачай его локально и удали с сервера: `shred -u ~/имя_ключа`.

Порядок действий после работы скрипта:

```bash
# 1. НЕ закрывая текущую сессию, проверь вход в новом окне:
ssh -p 2222 admin@IP_СЕРВЕРА

# 2. Убедись, что sudo работает:
sudo -v

# 3. Только после этого закрывай старую сессию.
```

## 🔍 Аудит портов

Перед настройкой фаервола скрипт смотрит `ss -tulnp` и показывает, что слушается — **сгруппированно по процессам**, чтобы даже сотни портов выглядели компактно:

```
  Слушается снаружи:
    tcp  nginx        80
    tcp  rw-core      2 порта: 443, 8443
    udp  rw-core      200 портов: 33069, 33078, 33158, … +ещё 197
    tcp  sshd         2222   ← порт SSH (открою отдельно)
  Локальные (127.0.0.0/8 и т.п. — фаервол их не касается): 8080/tcp (docker-proxy)
```

Дальше выбор:

1. **Открыть всё, что уже слушается извне** — вариант по умолчанию для работающего сервера: ничего из текущих сервисов не перестанет работать;
2. **Задать список вручную** — порт[/tcp|udp|both] или диапазон (`30000-40000/udp`), через запятую — вариант для чистого сервера под новый деплой;
3. **Ничего не открывать**.

При ручном списке скрипт предупредит об конфликтах — тоже по процессам, одной строкой:

```
[!] «rw-core» (udp): 200 портов слушаются, но их нет в списке — UFW закроет доступ извне: 33069, 33078, 33158, … +ещё 197
```

и наоборот: открыт порт, который пока никто не слушает — подсказка (норма до деплоя). Локальные (127.0.0.0/8, ::1), приватные и multicast-адреса в проверках не участвуют — фаервол на них не влияет.

## 🔁 Повторный запуск

Скрипт идемпотентен: его можно запускать сколько угодно раз. Это удобный способ «привести сервер в актуальное состояние» — система обновится, конфиги перезапишутся, ничего не сломается.

```bash
bash setup.sh --ports 443/tcp   # например, добавить порт
```

На уже настроенном сервере можно пропускать этапы, которые трогать не нужно:

```bash
# порты уже открыты руками, sshd настроен — только обновить и поставить Docker:
bash setup.sh --no-firewall --no-ssh
```

Противоречия разрешаются в пользу пропуска: `--no-ssh --ssh-port 2222` — порт меняться не будет, `--no-firewall --ports 443/tcp` — фаервол не тронется.

## 🧰 Полезные команды

### Система и ресурсы

```bash
htop                            # нагрузка, процессы
free -h && df -h                # память и диск
uname -r                        # версия ядра
uptime
timedatectl                     # время и таймзона
```

### Сеть и BBR

```bash
sysctl net.ipv4.tcp_congestion_control                # должно быть: bbr
sysctl net.core.default_qdisc                         # должно быть: fq
lsmod | grep bbr
ss -tulpn                                             # кто какие порты слушает
ip -br a                                              # IP-адреса кратко
cat /proc/sys/net/ipv4/icmp_echo_ignore_all           # 1 = ping заблокирован
curl -4 ifconfig.me                                   # внешний IP
```

### UFW / фаервол

```bash
ufw status numbered                        # все правила
ufw allow 443/tcp                          # открыть порт
ufw allow 8443/udp                         # открыть udp-порт
ufw allow from 1.2.3.4 to any port 3000    # доступ только с одного IP
ufw delete <номер правила>                 # удалить правило
ufw disable && ufw enable                  # перезапуск фаервола
# если UFW вдруг нет: apt install -y ufw
```

### Fail2ban

```bash
fail2ban-client status sshd               # кто в бане
fail2ban-client set sshd unbanip 1.2.3.4  # разбанить IP
tail -f /var/log/fail2ban.log
```

### Docker

```bash
docker ps                                    # запущенные контейнеры
docker logs -f --tail 100 <container>        # логи контейнера
docker compose pull && docker compose up -d  # обновить проект
docker stats                                 # потребление контейнеров
```

### Трафик и скорость

```bash
vnstat                # трафик за сегодня
vnstat -m             # по месяцам
vnstat -l             # трафик в реальном времени
speedtest-cli         # тест скорости
iperf3 -s             # режим сервера; с другой машины: iperf3 -c <IP сервера>
```

### Диагностика сети

```bash
mtr -rwzb 1.1.1.1     # трассировка + потери пакетов
nc -zv <host> <port>  # доступен ли порт
openssl s_client -connect <host>:443 -servername <host>   # проверить сертификат
tcpdump -ni any port 443                                  # пакеты в реальном времени
resolvectl status     # DNS
```

### Логи и входы

```bash
journalctl -xe                             # последние ошибки системы
journalctl -u ssh --since "1 hour ago"     # логи SSH
last -a | head                             # успешные входы
lastb | head                               # неудачные попытки (брутфорс)
```

### Обновление сервера вручную

```bash
apt update && apt full-upgrade -y && apt autoremove -y
reboot    # если обновилось ядро
```

## 🩺 Устранение неполадок

**Новый SSH-порт не пускает.** Открой VNC-консоль провайдера, войди под root и проверь: `ufw status` (порт открыт?), `sshd -T | grep port` (sshd слушает?), `journalctl -u ssh -n 50` (логи).

**Потерял ключ, пароль не подходит.** VNC-консоль провайдера → root по паролю. Дальше либо добавь свой ключ в `authorized_keys`, либо `passwd admin` и временно верни парольный вход (`PasswordAuthentication yes` в `/etc/ssh/sshd_config.d/99-hardening.conf`, потом `systemctl restart ssh`).

**Сервис недоступен извне, а локально работает.** Проверь аудит: `ufw status` — порт открыт? `ss -tulpn` — слушает ли сервис на `0.0.0.0`/`[::]`, а не только на `127.0.0.1`?

## ❓ FAQ

**Сервер не пингуется — это нормально?**
Да, скрипт блокирует ответы на ICMP. Мониторинги по TCP/HTTP продолжат работать, а ICMP-мониторинги — нет (добавь их IP в исключения или используй TCP-мониторинг). Блокировка ping не делает сервер невидимым — это лишь снижение заметности для простых сканеров.

**Безопасно ли запускать повторно?**
Да. Скрипт идемпотентен: обновит систему и перезапишет свои же конфиги.

**У admin нет пароля — так и задумано?**
Да. Вход только по ключу, sudo без пароля (NOPASSWD). Пароля нет — его нельзя подобрать или украсть через фишинг. Если нужен пароль для admin: `sudo passwd admin`.

**Почему меня выкидывает на root, а admin не пускает?**
Скорее всего, admin создан без ключа (вопрос про ключ пропущен). Его аккаунт без пароля — вход только по ключу. Добавь ключ: положи публичный ключ в `/home/<user>/.ssh/authorized_keys`, проверь права (700 на каталог, 600 на файл, владелец — пользователь).

**Куда скрипт отправляет мои данные?**
Никуда. Весь код открыт — можно прочитать перед запуском. Внешние запросы: apt-репозитории, GitHub (установщик Docker), api.ipify.org — один раз для показа твоего IP в итоговой сводке.

Скрипт меняет сетевые настройки и конфигурацию SSH. Используй на свой страх и риск и сначала тестируй на одноразовом сервере. Автор не несёт ответственности за потерю доступа к серверу. Используйте только в соответствии с законодательством вашей страны.
