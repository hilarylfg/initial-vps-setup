# 🚀 initial-vps-setup

**Интерактивная первоначальная настройка VPS**

Одна команда — мастер спросит всё нужное, покажет план и приведёт сервер в боевую готовность. Каждое действие проверяется по факту, итог — честная таблица, полный лог остаётся на сервере.

## ✨ Возможности

- 🧙 **Интерактивный мастер** — сам спросит всё и покажет план до любых изменений
- 👤 **Отдельный admin-пользователь** — sudo без пароля (NOPASSWD) с реальной проверкой, что sudo работает
- 🔑 **Только SSH-ключи** — вход по паролю отключается так, что его **не может перекрыть конфиг хостера** (файл с высшим приоритетом + проверка действующей конфигурации)
- 🔌 **Смена порта SSH работает всегда** — скрипт понимает socket activation (Ubuntu 22.10+), берёт фактический порт из прослушивания, а не из конфига
- 🔍 **Аудит портов** — покажет, что слушается, предложит открыть всё работающее одной опцией
- 🩺 **Честный отчёт** — каждое обещание проверяется: таблица `[OK]/[WARN]/[FAIL]` в конце, шаги не валят друг друга
- 🐕 **Режим doctor** — `bash setup.sh --doctor` проверяет сервер в любой момент, ничего не меняя
- 🎛 **Меню управления** — после настройки на сервере живёт команда `sudo vps`: чекбокс-панель со всеми возможностями, статус каждого пункта виден вживую, включай/выключай что нужно и применяй пачкой
- 📜 **Лог** — всё пишется в `/var/log/vps-setup-<дата>.log` (права 600), можно прислать клиенту/себе
- 🔄 **Обновление системы** — apt всегда обновляет индексы (даже с `--no-update`), ждёт освобождения локов
- 🔥 **UFW** — фаервол настроится сам; правила идемпотентны, при перезапуске не дублируются
- ⚡ **BBR + fq** — с проверкой обоих параметров по факту
- 🛡 **Fail2ban** — jail проверяется после запуска; `--no-fail2ban` реально не ставит пакет
- 🚫 **Отключение IPv6** — если хостер (контейнер) запрещает, скажет прямо и подскажет, где включать
- 🤫 **Блокировка ping** — sysctl, а если контейнер его запрещает — фолбэк через nftables с пережитием ребута
- 💾 **Swap** — создаётся на любом сервере (2 ГБ при RAM ≤ 2 ГБ, иначе 1 ГБ); если контейнер запрещает swapon — откатит файл и честно сообщит
- 🐳 **Docker** — официальный установщик, после установки проверяется живой демон, admin добавляется в группу
- ♻️ **Идемпотентность** — повторный запуск безопасен: без дублей ключей, правил и конфигов

## ⚡ Быстрый старт

Подключись к серверу и выполни одну команду:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hilarylfg/initial-vps-setup/main/setup.sh)
```

Мастер задаст вопросы и покажет план. Всё, что подтвердишь, применится; ответы можно менять.

Проверить сервер без каких-либо изменений (в любой момент, хоть сейчас):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hilarylfg/initial-vps-setup/main/setup.sh) --doctor
```

Автоматический прогон (флаги гасят свои вопросы; полностью без вопросов — запуск без терминала):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hilarylfg/initial-vps-setup/main/setup.sh) \
     --admin deploy \
     --ssh-key "$(cat ~/.ssh/id_ed25519.pub)" \
     --ssh-port 2222 \
     --ports 443/tcp,8443/udp \
     --timezone Europe/Amsterdam
```

> [!WARNING]
> Меняешь порт SSH — после работы скрипта проверь подключение **в новом окне терминала**, не закрывая текущую сессию. Скрипт сам проверит, что sshd слушает новый порт, но проверка входа с твоей машины — за тобой. Если что-то не так — аварийный вход через VNC-консоль провайдера (`root` + пароль, скрипт его не трогает).

## 🧙 Мастер настройки

Что спросит (везде Enter = значение по умолчанию):

| Вопрос | По умолчанию |
|---|---|
| Настраивать SSH? (порт, харденинг, запрет паролей) | да |
| Таймзона | не менять |
| Hostname | оставить текущий |
| Порт SSH | оставить как есть (текущий определяется по факту) |
| Пользователь для работы | создать `admin` (`-` — остаться под root) |
| SSH-ключ для admin | вставить свой / взять ключи root / сгенерировать на сервере / пропустить |
| Настраивать фаервол и порты? | да |
| Как открыть порты | перед этим покажет, что слушается: открыть всё слушающееся / список вручную / ничего |
| Обновлять систему? | да |
| Отключить IPv6 | нет |
| Блокировать ping | да |
| Создать swap | да |
| Поставить fail2ban | да |
| Харденинг SSH | да |
| Поставить Docker | да |
| Удалить cloud-init | нет |
| Отключить вход по паролю | да, если на сервере есть ключи |

Отвечаешь «нет» на этап — он полностью пропускается: sshd, фаервол и apt остаются ровно в том состоянии, в каком были. В конце мастер покажет **план настройки** — изменения начнутся только после подтверждения.

## 🚩 Флаги запуска

Полный список: `bash setup.sh --help`. Флаг задаёт ответ заранее — такой вопрос в мастере не спрашивается.

| Флаг | Описание |
|---|---|
| `--doctor` | только проверить сервер и показать отчёт, ничего не меняя |
| `--ssh-port PORT` | сменить порт SSH (работает и при socket activation) |
| `--ports 443/tcp,8443/udp` | открыть порты; протокол: `tcp` (по умолчанию), `udp` или `both`; диапазоны: `30000-40000/udp` |
| `--timezone Europe/Moscow` | установить таймзону |
| `--admin USER` | создать пользователя с sudo без пароля (NOPASSWD) |
| `--ssh-key "KEY"` | публичный ключ для admin (или root, если admin не задан); можно несколько раз |
| `--key-from-root` | скопировать ключи из `/root/.ssh/authorized_keys` |
| `--generate-key` | сгенерировать ed25519-пару на сервере (приватный ключ показывается один раз) |
| `--hostname NAME` | задать hostname |
| `--disable-ipv6` | отключить IPv6 |
| `--no-update` | не обновлять пакеты (apt update всё равно пройдёт — иначе установка сломалась бы) |
| `--no-firewall` | **не трогать фаервол и порты вообще** — UFW остаётся как есть |
| `--no-ssh` | **не менять настройки sshd вообще** — порт, харденинг и пароли остаются как есть |
| `--no-docker` | не ставить Docker |
| `--no-fail2ban` | не ставить и не настраивать fail2ban |
| `--no-block-ping` | не блокировать ping (и снять блокировку прошлых запусков сразу) |
| `--no-swap` | не создавать swap |
| `--no-ssh-harden` | не применять харденинг SSH |
| `--disable-ssh-password` | вход только по ключам. ⚠️ Ключ должен быть **уже на сервере** или передан флагом! |
| `--purge-cloudinit` | удалить cloud-init. ⚠️ Если хостер раздаёт через него сеть/порт SSH — не надо |

## ⚙️ Что делает скрипт

| Шаг | Что происходит | Проверка после |
|---|---|---|
| 🔄 Обновление | `apt update` всегда; `upgrade` — если не `--no-update` | пакеты/индексы |
| 📦 Базовый софт | curl, git, jq, sudo, htop, vnstat, mtr, iperf3 и др. | каждый пакет на месте |
| 🕐 Время и имя | NTP + таймзона и hostname | `timedatectl show`, `hostname` |
| 👤 Admin | пользователь + `sudo` + NOPASSWD | `sudo -n` реально от его имени |
| 🔑 Ключи | `authorized_keys` с проверкой каждого ключа, без дублей | количество ключей |
| ⚡ BBR + fq | sysctl | оба параметра по факту |
| 🚫 IPv6 | sysctl; на контейнерах — честный FAIL с подсказкой | `/proc/sys` |
| 🤫 Ping | sysctl; если запрещён — nftables-фолбэк с юнитом на ребут | `/proc/sys` или nftables |
| 📈 Лимиты | nofile 1M, журнал systemd 200 МБ | файл на месте |
| 🔐 SSH | порт/харденинг/запрет паролей **в 00-hardening.conf** (приоритет выше cloud-init), атомарная запись с откатом, socket activation | фактический порт + `sshd -T` |
| 🛡 Fail2ban | jail на актуальный SSH-порт, бэкап старого jail.local | `fail2ban-client status sshd` |
| 🔥 UFW | deny incoming, rate-limit SSH, порты из мастера; перезапись только своих `node`-правил | `ufw status` + правило SSH |
| 💾 Swap | файл + fstab; при запрете — откат и честный FAIL | `swapon --show` |
| 🐳 Docker | официальный установщик; admin в группу `docker` | `docker info` (живой демон) |

## 🩺 Отчёт и проверка (doctor)

В конце каждой установки — таблица:

```
  [ OK ] Пользователь admin    sudo без пароля работает (root-шелл: sudo -i)
  [ OK ] SSH порт              2222 (слушается)
  [WARN] Ping (ICMP)           sysctl запрещён контейнером — режется nftables
  [FAIL] BBR + fq              congestion=cubic — ядро без BBR (нужно 4.9+)
  Итог: 14 OK, 1 предупреждений, 1 неудач
```

- **OK** — проверено по факту, работает; **WARN** — работает, но с нюансом; **FAIL** — не получилось, с подсказкой что делать. Падение одного шага не останавливает остальные.
- **Лог** всего прогона: `/var/log/vps-setup-<дата>.log`, права 600 — удобно приложить, когда разбираешься с клиентским сервером.
- **doctor** — те же проверки в любой момент, без изменений:

```bash
bash setup.sh --doctor
```

exit-код: 0 — всё OK/WARN, 1 — есть FAIL (можно использовать в мониторинге).

## 🎛 Меню управления (`vps`)

Мастер настраивает сервер один раз, а **меню — это пульт на каждый день**. Надо быстро выключить IPv6, открыть порт, добавить ключ админу или снести Docker — не вспоминай флаги, просто открой меню:

```bash
sudo vps
```

Команда `vps` ставится скриптом **при первом запуске** (`/usr/local/bin/vps`) — даже если мастер не доведён до конца. Без неё меню открывается так же: `bash setup.sh menu`.

```
═══ vps меню · srv1 · SSH :2222 · v1.1.0 ═══
 ↑↓/цифры — выбор · пробел — вкл/выкл · Enter — значение · a — применить · q — выход
─────────────────────────────────────────────────────────────
  [x] BBR + fq (ускорение TCP)   включён
  [ ] IPv6                       включён   → станет: отключён
  [x] Блокировать ping (ICMP)    блокируется
  [x] Харденинг SSH              включён
  [ ] Вход по паролю SSH         запрещён (только ключи)
  [x] Fail2ban                   активен
  [x] Фаервол UFW                active
  [x] Swap                       есть
  [x] Docker                     установлен
  …
─────────────────────────────────────────────────────────────
 W визард · D doctor · P аудит портов · I инфо · U обновить vps
 К применению: 1 — жми a
```

**Как это работает:** каждый пункт показывает **живой статус** сервера (те же проверки, что в doctor). Пробел переключает желаемое состояние — изменённые пункты помечаются «→ станет: …». Клавиша `a` показывает план изменений, спрашивает подтверждение и применяет **только изменённые пункты** — всё остальное не трогается. После применения — та же таблица `[OK]/[WARN]/[FAIL]`, и меню обновляет статусы.

| Пункт | Можно | Как |
|---|---|---|
| BBR + fq, IPv6, ping, лимиты | вкл/выкл | sysctl-конфиги скрипта, проверка по факту |
| Харденинг SSH | вкл/выкл | пересборка `00-hardening.conf` с проверкой `sshd -t` |
| Вход по паролю | вкл/выкл | выключение — только при живом ключе; включение — с двойным подтверждением |
| Порт SSH | сменить | как в мастере: порт закрепляется, проверяется слушанье; ⚠️ после — проверь вход в новом окне |
| Fail2ban, Docker, swap | поставить / удалить | удаление Docker — с двойным подтверждением (контейнеры и образы стираются) |
| Фаервол UFW | вкл/выкл | выключение сохраняет правила; включение ставит rate-limit на актуальный SSH-порт |
| Порты наружу | задать список | тот же аудит портов, что в мастере; перезапись только `node`-правил |
| cloud-init | удалить | с предупреждением про хостера |
| Обновление системы | запустить | `apt update` + `upgrade` |
| Таймзона, Hostname | изменить | проверка по факту |
| Админ-пользователь | создать / добавить ключи | удобно, когда потерял ключ — добавь новый через меню |

Буквенные команды внизу экрана:

| | |
|---|---|
| `W` | полный мастер настройки (как при первом запуске) |
| `D` | doctor — проверка сервера без изменений |
| `P` | аудит портов: что слушается снаружи и что открыто в UFW |
| `I` | инфо о сервере: RAM, диск, нагрузка, IP, трафик vnstat |
| `U` | обновить `vps`: скачать свежий скрипт с GitHub (с проверкой синтаксиса) и заменить команду |

Каждая применённая пачка логируется в `/var/log/vps-setup-menu-<дата>.log` (права 600).

> [!WARNING]
> Смена порта SSH из меню — то же самое, что в мастере: скрипт переключит sshd и UFW, но **проверь вход по SSH в новом окне терминала**, не закрывая текущую сессию.

## 🔐 Доступ к серверу после настройки

- **Работай под admin-пользователем.** Он в группе `sudo`, право root — без пароля (NOPASSWD, работа проверяется скриптом). `sudo -i` — полноценный root-шелл.
- **Вход по паролю отключается только при живом ключе.** Если ключ есть у admin — root закрывается полностью. Если ключ только у root — root остаётся доступен по ключу (`prohibit-password`), чтобы не потерять доступ.
- **У admin нет пароля — это осознанно.** Пароль заблокирован, вход только по ключу; sudo срабатывает без пароля.
- **Аварийный вход** — VNC-консоль провайдера: там root доступен со своим паролем (его скрипт не трогает).
- **Порт SSH закрепляется в конфиге** (`00-hardening.conf` + drop-in для ssh.socket) — не слетит к 22 при ребуте.
- Если выбрал «сгенерировать ключ на сервере» — приватный ключ показывается **один раз** (при повторных прогонах не повторяется) и сохраняется в `/root/`. Скачай и удали: `shred -u ~/имя_ключа`.

Порядок действий после работы скрипта:

```bash
# 1. НЕ закрывая текущую сессию, проверь вход в новом окне:
ssh -p 2222 admin@IP_СЕРВЕРА

# 2. Убедись, что sudo работает:
sudo -v

# 3. Только после этого закрывай старую сессию.
```

## 🔍 Аудит портов

Перед настройкой фаервола скрипт смотрит `ss -tulnp` и показывает, что слушается — **сгруппированно по процессам**:

```
  Слушается снаружи:
    tcp  nginx        80
    tcp  rw-core      2 порта: 443, 8443
    udp  rw-core      200 портов: 33069, 33078, 33158, … +ещё 197
    tcp  sshd         2222   ← порт SSH (открою отдельно)
  Локальные (127.0.0.0/8 и т.п. — фаервол их не касается): 8080/tcp (docker-proxy)
```

Дальше выбор:

1. **Открыть всё, что уже слушается извне** — по умолчанию для работающего сервера: ничего не перестанет работать;
2. **Задать список вручную** — порт[/tcp|udp|both] или диапазон (`30000-40000/udp`);
3. **Ничего не открывать**.

При ручном списке скрипт предупредит о конфликтах — одной строкой на процесс: `«rw-core» (udp): 200 портов слушаются, но их нет в списке — UFW закроет доступ извне: …`. Локальные (127.0.0.0/8, ::1), приватные (10/8, 172.16/12, 192.168/16), CGNAT (100.64/10), IPv6 ULA/link-local/multicast и порт SSH в проверках не участвуют.

## 🔁 Повторный запуск

Точечные изменения на настроенном сервере удобнее делать через меню (`sudo vps`) — см. [Меню управления](#-меню-управления-vps). Флагами тоже можно:

Скрипт идемпотентен: конфиги перезаписываются, ключи не дублируются, `node`-правила UFW перезаписываются по новому списку (чужие правила не трогаются), приватный ключ при `--generate-key` повторно не показывается.

```bash
bash setup.sh --ports 443/tcp          # заменить список открытых node-портов
bash setup.sh --no-firewall --no-ssh   # обновить систему, ничего больше не трогая
```

Противоречия разрешаются в пользу пропуска: `--no-ssh --ssh-port 2222` — порт не сменится; `--no-firewall --ports 443/tcp` — фаервол не тронется.

## 🧰 Полезные команды

### Система и ресурсы

```bash
htop                            # нагрузка, процессы
free -h && df -h                # память и диск
uname -r                        # версия ядра
uptime
timedatectl                     # время и таймзона
bash setup.sh --doctor          # полная проверка состояния
```

### Сеть и BBR

```bash
sysctl net.ipv4.tcp_congestion_control                # должно быть: bbr
sysctl net.core.default_qdisc                         # должно быть: fq
lsmod | grep bbr
ss -tulpn                                             # кто какие порты слушает
ip -br a                                              # IP-адреса кратко
cat /proc/sys/net/ipv4/icmp_echo_ignore_all           # 1 = ping заблокирован (sysctl)
nft list ruleset | grep echo-request                  # ping-блок через nft-фолбэк
curl -4 ifconfig.me                                   # внешний IP
```

### UFW / фаервол

```bash
ufw status numbered                        # все правила
ufw allow 443/tcp                          # открыть порт
ufw allow 8443/udp                         # открыть udp-порт
```

## 🩺 Устранение неполадок

**Новый SSH-порт не пускает.** Открой VNC-консоль провайдера, войди под root и проверь: `ss -tlnp | grep sshd` (где sshd?), `ufw status` (порт открыт?), `sshd -T | grep port`. При socket activation порт задаёт `ssh.socket` — скрипт делает это сам, но руками: `systemctl disable --now ssh.socket && systemctl enable --now ssh.service`.

**Потерял ключ, пароль не подходит.** VNC-консоль провайдера → root по паролю. Добавь свой ключ в `/home/<user>/.ssh/authorized_keys` (права: 700 каталог, 600 файл, владелец — пользователь).

**Сервис недоступен извне, а локально работает.** `ufw status` — порт открыт? `ss -tulpn` — слушает ли сервис на `0.0.0.0`/`[::]`, а не только на `127.0.0.1`?

**Сервер на контейнере (LXC/OpenVZ) и что-то из списка не работает.** Ping, IPv6 и swap физически управляются хостером: скрипт отрапортует FAIL/WARN с причиной. Ping скрипт компенсирует nftables-фолбэком; IPv6 и swap включаются только в панели хостера.

## ❓ FAQ

**Сервер не пингуется — это нормально?**
Да, скрипт блокирует ответы на ICMP. Если контейнер запрещает sysctl — включается nftables-фолбэк (видно в отчёте как WARN). Мониторинги по TCP/HTTP продолжат работать.

**Безопасно ли запускать повторно?**
Да. Конфиги перезаписываются идемпотентно, ключи и правила не дублируются. `node`-правила UFW перезаписываются по актуальному списку `--ports`; правила, добавленные руками без метки `node`, скрипт не трогает.

**У admin нет пароля — так и задумано?**
Да. Вход только по ключу, sudo без пароля (NOPASSWD). Если нужен пароль: `sudo passwd admin`.

**Как проверить, что всё работает, через неделю?**
`bash setup.sh --doctor` — полная проверка без изменений: BBR, ping, UFW, fail2ban, Docker, sshd, время.

**Почему BBR/ping/IPv6 не включились?**
Смотри отчёт: там точная причина. На контейнерной виртуализации (LXC/OpenVZ) часть параметров ядра управляется хостером — это физическое ограничение, не баг скрипта.

**Куда скрипт отправляет мои данные?**
Никуда. Весь код открыт — можно прочитать перед запуском. Внешние запросы: apt-репозитории, GitHub (установщик Docker), api.ipify.org — один раз для показа твоего IP в итоговой сводке. Лог с настройками остаётся на самом сервере (`/var/log/vps-setup-*.log`, права 600).
